# Compass Plan - 2026-10-27

## Goal
Build Compass hackathon demo: situation-aware exploration of prediction-market topics backed by a Living Event Graph + Agent Squad, using Kalshi (markets/events) and GDELT (news) as the two demo sources.

## Success Criteria
- User can pick a Kalshi event, see related GDELT news, evidence, and hypotheses as one connected graph with timeline.
- Graph updates when re-polled: new markets/news appear as nodes, linked to existing events.
- Agent Squad runs end-to-end without keys via rule-based fallback, and uses a real LLM only if configured.
- Demo runs locally from this empty Python repo with one command and seeded sample data.

## Approach
One codebase, service-ready. Monorepo with five packages matching user layers, each behind a small interface. Single-process run for hackathon, splittable later. Kalshi uses public REST reads for events/markets; GDELT uses DOC API artlist JSON queries.
- 1 Information Sources: SourcePlugin interface (fetch + normalize). Kalshi + GDELT now, new source = new plugin.
- 2 Event Processing: pure normalize + change-detect functions, triggers investigations.
- 3 Agent Squad Orchestrator: independent component. Agent interface + model factory using LangChain unified chat-model API so providers swap by config. Roles: Scout (discover) + Investigator (evidence) + Connector (link) fan-out, then Skeptic as gate.
- 4 Living Event Graph: storage interface (file-backed JSON now, real DB later) via Graph Update API (Validate | Commit | Record). Time-versioned edges.
- 5 Interactive Workspace: Cytoscape.js graph view + human feedback (Explore | Ask | Challenge) feeding new tasks to orchestrator.

## Steps
Build Days 1-5. Demo + iterate Days 6-10.
1. Day 1 Scaffold: `compass/` monorepo (sources, processing, squad, graph, workspace), `data/` seed dir, env config, single run entrypoint.
2. Day 1-2 Graph + Update API: nodes Event/Market/Article/Hypothesis, time-versioned edges, Validate|Commit|Record, idempotency via ticker + URL hash.
3. Day 2 Sources + Processing: Kalshi + GDELT plugins (fetch + normalize), change-detect by price/volume/new-article deltas.
4. Day 3-4 Squad: Scout + Investigator + Connector fan-out, Skeptic as veto gate, LangChain model factory with rule-based fallback.
5. Day 4-5 Workspace: Cytoscape.js view (cap ~200 nodes, time/confidence filter), detail + timeline, typed feedback (Explore/Ask/Challenge) to orchestrator queue.
6. Day 5 Seed + freeze: 2-3 topics captured, offline run works, cut scope.

## Validation Plan
- `python -m compass.seed` then `python -m compass.run --once`: expect exit 0, graph JSON created, counts printed.
- Query check: fetch one event detail, confirm linked markets + articles render.
- Offline check: disconnect network, re-run on seed data, same graph loads.

## Risks / Open Questions
- 10-day limit (5 build + 5 demo): freeze scope Day 5, no new sources after Day 2.
- Rate limits / network at venue: mitigated by seeded offline mode.
- LLM key absent: default to rule-based squad, mark hypotheses provisional.
- Open: which 2-3 demo topics? Pick by Day 2.
- Non-goals: auth, multi-user, realtime sockets, additional sources, true microservice deploy.
